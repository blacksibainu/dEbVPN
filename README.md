# DebVPN

Windows-клиент для [VPN Gate](https://www.vpngate.net/) (бесплатная публичная сеть
серверов, University of Tsukuba) — выбираешь страну на карте, приложение
подключается через один реальный OpenVPN-сервер этой страны. Не Tor: один
хоп, один сервер, обычный VPN-туннель (TUN-адаптер через Wintun), а не
анонимная многоузловая сеть.

GUI — WebView2 (HTML/CSS/JS встроены прямо в `src/main.cpp` одной строкой),
бэкенд — C++/Win32.

## Статус на данный момент

Рабочее, но не полностью стабильное:

- Список серверов VPN Gate грузится и парсится надёжно (см.
  `VpnGateClient.cpp` — гонка по всем IP из DNS, т.к. часть адресов
  VPN Gate периодически блокируется на уровне провайдера/сети).
- Подключение через `openvpn.exe` **иногда зависает** на этапе
  management-хендшейка (`state on` подтверждается, а `>HOLD:` от процесса
  не приходит — нестабильно, не до конца локализовано). При зависании:
  прочитать `%LOCALAPPDATA%\DebVPN\ovpn\vpngate.log` — если файла нет
  вообще, значит `openvpn.exe` не успел стартовать; если есть — смотреть,
  на какой строке остановилось.
- Планировщик заданий (задумывался, чтобы UAC спрашивался один раз, а не
  на каждое подключение) пока не срабатывает — см. `EnsureScheduledTask`/
  `RunScheduledTask` в `OpenVpnService.cpp`, там же рабочий запасной путь
  через прямой `ShellExecuteEx("runas")` (UAC на каждое подключение).

## Архитектура

```
src/
  main.cpp            WinMain, окно, WebView2, HTML/CSS/JS интерфейса
  VpnGateClient.h/.cpp Список серверов VPN Gate (WinHTTP) + декодирование
                        base64-конфигов
  OpenVpnService.h/.cpp Запуск openvpn.exe (через runas), протокол
                        OpenVPN Management Interface (TCP localhost)
  CountryData.h        Справочник стран (код, флаг, координаты для карты)
  WorldMapPath.h        Контур материков для карты (сгенерирован из
                        Natural Earth 110m, см. ниже)
  Utf8.h                wide<->utf8 хелперы

openvpn/bin/            Бинарники OpenVPN 2.6.14 + wintun.dll (взяты из
                         официального MSI-инсталлятора, см. ниже)
```

Мост GUI <-> C++: `window.chrome.webview.postMessage(JSON)` в одну сторону,
`ICoreWebView2::PostWebMessageAsJson` в другую. Все действия с Tor/OpenVPN
идут в фоновом потоке (`OpenVpnController` — очередь задач + воркер),
события в UI прилетают через `PostMessageW` + `WM_APP_OVPN_EVENT`.

### Почему не системная служба

Изначально пытались переиспользовать официальную службу OpenVPN
("Interactive Service", `openvpnserv2.exe`) — так делает штатный OpenVPN
GUI, без UAC на каждое подключение. Оказалось, что `openvpnserv2.exe` в
актуальном MSI — .NET/Mono-сборка с другим протоколом, несовместимым с
открытыми исходниками (`interactive.c` на GitHub). Переписывать под
неизвестный протокол не стали — сейчас каждое подключение поднимает
`openvpn.exe` напрямую через `ShellExecuteEx("runas")`.

### Почему не запрашиваем права на всё приложение

WebView2/Chromium официально не поддерживает запуск процесса-хоста от
имени администратора — поймали реальный краш при тестировании именно на
этом. Права запрашиваются точечно, только на `openvpn.exe`.

## Сборка

Нужны: Visual Studio 2022 Build Tools (или полная VS) с компонентом C++ и
Windows SDK, CMake. vcpkg использовать не обязательно устанавливать
отдельно — подойдёт тот, что идёт в комплекте VS Build Tools
(`VC\vcpkg\vcpkg.exe`), путь к нему прописан в `CMakePresets.json`.

```powershell
cmake --preset default
cmake --build build --config Release
```

Собранный `DebVpn.exe` и всё нужное (`openvpn/`, `WebView2Loader.dll`)
окажутся в `build\Release\`.

## Файл `openvpn/bin/`

Бинарники (`openvpn.exe`, DLL, `wintun.dll`) уже лежат в репозитории —
переизвлекать не нужно. Если когда-нибудь понадобится обновить версию
OpenVPN: скачать MSI с `swupdate.openvpn.net/community/releases/`,
распаковать через `7z x installer.msi` (обычный установщик не подходит —
не даёт файлы напрямую), файлы `libssl_3_x64.dll` и подобные внутри MSI
почему-то с подчёркиваниями вместо дефисов — переименовать в
`libssl-3-x64.dll` и т.п. (иначе `openvpn.exe` не найдёт зависимости).

## Карта (`WorldMapPath.h`)

Сгенерирована скриптом на Node из `world-atlas@2/land-110m.json`
(TopoJSON, Natural Earth), спроецирована эквидистантно с разрывом полигонов
на антимеридиане (иначе Россия/Антарктида рисуются одной линией через всю
карту). Скрипт разовый, в репозитории не хранится — при необходимости
пересоздать: конвертация TopoJSON arcs → SVG path, разрыв subpath там, где
соседние спроецированные точки скачут больше чем на половину ширины карты.

## Известные ограничения

- Только Windows (WebView2, Win32 API).
- Игры и любой UDP-трафик через это приложение раньше (Tor-версия) не
  ходили в принципе; с переходом на OpenVPN технически должно быть ОК
  (полноценный TUN), но не проверялось из-за нестабильности подключения.
- Список стран VPN Gate меняется каждые несколько минут (сервис на
  добровольных серверах) — это нормально, не баг.
